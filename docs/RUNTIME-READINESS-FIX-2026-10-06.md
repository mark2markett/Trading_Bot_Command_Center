# Runtime readiness repair

Based on feat/options-m7 native 26ea7cb (patch-equivalent cloud 2f7bef3), followed by the already reviewed SIP client and interruption patches. One shared $100,000 paper account was explicitly selected by the operator.

The account is initial capital plus all realized trade P&L and fresh marked unrealized P&L across the fleet. It never sums per-bot initial balances and never reports simulated values as broker equity. Initialization requires a flat, entirely paper fleet and is idempotent; a different capital amount requires a separate accounting decision. Configuration and valid valuations are audited/persisted. Closed trades remain part of the account rather than resetting losses.

The server refreshes open-position quotes each risk-monitor pass. Stock marks use positive last prices with valid quote timestamps; option marks use the current validated bid/ask midpoint, since quoteTime does not date lastPrice. Marks older than 90 seconds or materially future timestamps are refused. Missing values block new entries, including spreads, and preserve risk-reducing exits. Gross exposure includes marked positions and reserved pending opening orders; all legs of a spread must fit the cap together. Daily-loss and portfolio-drawdown entry checks use shared account P&L. Existing drawdown ladder actions use persisted paper account history. This is simulated account valuation, not a live brokerage reconciliation.

Paper lifecycle writes and risk/entry publication commit atomically. Valuation uses a consistent SQLite read transaction. Daily fills publish their position with the fill, and rejection audit records commit before the rejection exception is raised. Provider calls occur outside the intraday/spread ledger transaction; daily paper execution inside its transaction uses only the local paper broker.

History polls reuse the same symbol/day response within a minute and refresh across minute boundaries. Each process honors provider Retry-After cooldowns by endpoint without sleeping or blocking independent quote endpoints. This reduces normal history request frequency from four calls per symbol/minute to one. It is not a shared global quota across M2M applications; 429 can still occur and remains a logged retryable outage.

`python scripts/native_readiness.py --configuration-only` checks account, exact five-paper-bot registration, fleet controls, server/risk-monitor freshness, and scanner/feed configuration. It never certifies live readiness. During 09:35–09:39 Eastern, run without that flag: actual Windows task state, live quote/minute-history freshness, and today's authenticated scanner snapshot are required. Missing credentials, absent equity, failed probes and pending scanner results fail the gate. `closed_loop.py --require-ready` requires this gate before its disposable sandbox tests. Ordinary closed-loop runs clearly state their deployment limitation.

The scanner producer remains platform branch feat/cc-sip-scanner, e8146e8. Production deployment, Redis/provider configuration, the dedicated matching secret, and a successful morning preparation/publication are still required. Publishing a feature branch alone is insufficient. Native scheduler tasks remain interactive; keep the Windows user signed in.
